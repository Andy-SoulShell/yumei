# 角色创建

创建页让用户表达角色偏好，再按文字设定生成独立形象。保留原来的六个主步骤，选择后自动切换属性，每组的完整图片全部展开。

| 优先级 | 问题与影响                                     | 调整                                                                     |
| ------ | ---------------------------------------------- | ------------------------------------------------------------------------ |
| P0     | 选项素材被保存为参考图，角色身份与用户选择混淆 | 前端只提交文字；后端文生图使用空参考图列表，只保存生成结果               |
| P1     | 属性被拆成额外的“下一步”，图片被裁切后难以判断 | “下一步”只切换主步骤；选中属性后自动继续；完整图片全部展开，取消选项翻页 |
| P2     | 居中窄容器、大标题与多层卡片浪费空间           | PC 全宽工作区，左侧步骤、中间选项、右侧标签；小屏收起摘要                |

## 视觉规则

选项图统一为 YUMEI 自带 ComfyUI 生成的 `studio-v2` 素材，共 124 张，保持 512×800 完整画幅。统一浅暖灰背景、柔和左上方光线、深蓝与米白服装基调；写实与动漫保留各自的表现方式。发型采用头肩视角，体型采用完整站姿，模板通过服装与相关道具呈现身份。

- 字号：标题 22px、区域标题 20px、正文 14px、辅助文字 12px；手机标题缩至 18px。
- 间距：8 / 12 / 16 / 24px；圆角：8 / 12px。
- 色彩：复用 YUMEI 主题变量；选中状态使用主色边框与勾选标识。
- 图片：完整展示 512:800 的原图，使用 `object-fit: contain`。PC 多列平铺、手机双列，当前组的全部选项同时渲染，不提供翻页或横向轮播。手机可以自然上下滚动查看所有完整图片，底部操作区固定。
- 色板：PC 三列、手机两列。
- 快速改善：精简页头、恢复完整图片、选择后自动继续、固定操作区、保留返回调整入口。

## 行为

风格 → 模板 → 外观 → 身材 → 设定 → 生成并创建。保留六个主步骤，“下一步”和“上一步”只切换主步骤。外观按原顺序：气质 → 肤色 → 瞳色 → 发色 → 发型；身材按原顺序：体型 → 胸部大小 → 臀部大小，男性仅体型。

点击风格或模板后自动前进；外观和身材选中后短暂停留显示勾选，再自动切到下一属性，最后一项完成后进入下一主步骤。已完成步骤与属性可返回调整；手动切换时取消尚未发生的自动跳转。自动切换后焦点落到新标题，便于键盘和读屏继续操作。角色生成必须由用户明确点击“生成并创建”，自动前进不会提交创建请求。

切换性别或画风会清除不适用的选项。模板只提供文字起点。

选项图片不被下载为上传文件，也不作为生成底图、角色参考图或头像。新建请求只提交 `generatePortrait: true` 和文字资料。服务端调用图片服务的 `text` 模式，参考图列表为空；生成成功并保存后才创建角色。失败时保留前端输入，并返还原周期图片额度。运营方生成沿用图片额度和限流；BYOK 与自托管沿用现有豁免规则。

既有角色的编辑、头像上传和旧接口的预设/手动上传能力继续保留。通过旧预设链接进入新向导时会填充文字，并生成新的形象。

## 验证

前端流程：`node node_modules/vitest/vitest.mjs run --config vitest.explore.config.ts`。

生成与接口：`node node_modules/vitest/vitest.mjs run --config vitest.creator.config.ts`。接口测试使用替身，不写应用数据库。fal 的纯文字端点及 PNG 输出参数依据[官方接口文档](https://fal.ai/models/xai/grok-imagine-image/api)。

浏览器验证覆盖桌面与手机的选项显示、前后步、摘要和固定操作区；类型检查、静态检查和构建应同时通过。

## 素材重生成

`node node_modules/tsx/dist/cli.mjs scripts/regenerate-creator-assets.ts` 复用项目的 `ComfyUIClient` 和 Qwen Image 2.1 工作流，读取现有环境配置。逐张保存进度，重新运行会跳过提示词、种子与成品一致的已完成项；`--only` 可指定分支或选项前缀。固定分支种子使同组构图与人物风格更稳定，明确的属性描述优先于通用美术规范。

生成稿与审看图保存在忽略目录 `output/creator/generated-v2/`。`scripts/creator-assets-media.py` 使用 Pillow 验证尺寸、哈希和非空画面，并生成逐组审看图；只有全部 124 张完成后，`--publish` 才会将完整画面编码为 WebP，替换站内素材。提示词、种子、原稿及 WebP 哈希见 `creator-assets-v2.json`。

原始 PNG 的画面内容由 YUMEI 生图链路生成，Pillow 仅负责检查、审看图排版及 WebP 编码。选项 URL 带素材版本参数，刷新后直接读取新图。
