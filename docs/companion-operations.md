# 陪伴功能运行与发布手册

适用当前开发阶段的最终 schema。数据库使用 UTC；用户日历、记忆日期和主动联系使用账号保存的 IANA 时区。完整实现及测试证据见 [升级验收记录](companion-upgrade-plan.md)。

## 初始化与发布

当前迁移只保留 `drizzle/0000_init.sql` 及对应元数据。旧开发数据库需要重建；不能在带旧迁移记录或旧表的库上执行新初始化 SQL。生产模式在监听端口前自动迁移，失败时拒绝启动。上传文件保存在独立卷，不随数据库重建清除。

发布顺序：

1. 完成类型、Lint、格式、完整测试、时区专项和构建；记录 Git 提交及镜像 ID。
2. 保存匹配版本的数据库逻辑备份、上传文件快照和部署配置。备份含私人聊天与加密密钥，存放在受限目录；不要写入 Git 或工单。
3. 先构建新镜像，再停止应用；仅重建明确指定的开发数据库，保留 MySQL 和上传数据卷。已有账号、聊天和偏好会从新库重新开始。
4. 启动应用，确认 `/healthz` 和 `/readyz` 均返回 HTTP 200，容器健康；浏览器检查首页、登录入口和静态资源。
5. 在合成账号上验证创建角色、流式对话、停止/补发/刷新恢复、记忆更正与偏好保存。真实供应商质量另按下述样本验收。

常用本地命令（测试入口只加载专用测试配置）：

```powershell
node scripts/test.mjs --reset
node scripts/test.mjs
$env:TZ = 'Asia/Shanghai'
node scripts/test.mjs server/notification-frequency.test.ts server/proactiveContact.test.ts server/memorySemantics.test.ts
Remove-Item Env:TZ
node node_modules/typescript/bin/tsc --noEmit
node node_modules/eslint/bin/eslint.js . --max-warnings 0
node node_modules/prettier/bin/prettier.cjs --check .
node scripts/run.mjs build
docker compose config --quiet
docker compose build app
docker compose up -d
```

`--reset` 会校验库名包含 `test` 且与应用库不同，再清空该测试库。不要把应用连接地址传给测试进程。开发库重建应在停止应用后使用数据库管理工具执行，不能用删除全部 Docker 卷代替。

## 配置与降级

修改环境变量后重启应用。完整配置与凭据说明见 [环境模板](../.env.example)。

| 配置                                                | 默认值    | 作用与边界                                                                                                |
| --------------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------- |
| `COMPANION_MEMORY_ENABLED`                          | `1`       | 全局记忆开关；角色也可独立暂停。关闭后不发起新的记忆提取、索引、查询和摘要调用                            |
| `COMPANION_PROACTIVE_ENABLED`                       | `1`       | 全局主动联系开关；账号仍须显式开启，发送前再次校验                                                        |
| `MEMORY_EXTRACTION_MODEL`                           | 空        | 空值沿用当前服务选择的聊天模型                                                                            |
| `MEMORY_EMBEDDING_MODEL`                            | 空        | 空值或当前服务不支持时使用词面召回；不改用另一服务接收私人数据                                            |
| `AI_DAILY_TASK_LIMIT`                               | `200`     | 每用户每 UTC 日的内部 AI 尝试次数，范围 1～10000；覆盖记忆、摘要、服务端 TTS 和转写。实际失败调用也占次数 |
| `AI_TASK_TIMEOUT_MS`                                | `30000`   | 上述内部调用超时，范围 100～120000 毫秒                                                                   |
| `CHAT_CONTEXT_CHAR_LIMIT`                           | `80000`   | 上下文 UTF-16 字符预算，范围 64000～160000；完整保留已接受的当前补充，历史和记忆分块预算                  |
| `CHAT_MAX_OUTPUT_CHARS`                             | `16000`   | 单次文字输出上限，范围 1000～32000                                                                        |
| `CHAT_REPLY_TIMEOUT_MS`                             | `120000`  | 上游文字生成总超时，范围 5000～300000 毫秒                                                                |
| `CHAT_STREAM_CONCURRENCY` / `CHAT_USER_CONCURRENCY` | `4` / `3` | 全局和每用户的流式生成并发上限；范围分别为 1～32、1～10                                                   |
| `PROACTIVE_TICK_MS`                                 | `60000`   | 主动联系调度间隔，范围 1000～3600000 毫秒                                                                 |
| `PROACTIVE_PUSH_TIMEOUT_MS`                         | `8000`    | 单设备推送超时，范围 100～20000 毫秒，短于 30 秒投递租约                                                  |

聊天按所选服务和凭据调用，运营方可配置兼容网关；用户 OpenRouter BYOK 仅送往官方端点。Embedding 异常、未配置或预算耗尽时保留词面检索。记忆或摘要失败不阻塞文字回复；图片失败独立结算，语音失败保留文字。客户端停止或补发会取消播放；切换账号、会话和卸载后的迟到结果会丢弃。

Web Push 需要成对 VAPID 公私钥及浏览器订阅。调度和站内消息不依赖 VAPID；未配置推送时，显式同意的联系仍可在站内查看。用户偏好保存与当前设备订阅是两个独立入口。

## 恢复、结算与隐私

- 文字任务和分句在 MySQL 持久化。同一客户端请求 ID 绑定原账号及请求内容，重试不会重复扣额度。网络断开可重连；主动停止会终止旧轮。部分有效输出保留一次业务用量，零输出失败或取消补偿一次。供应商实际调用及成本与业务额度分别统计。
- 进程启动恢复调度，过期租约由共享数据库重新领取或结束；运营排查先看任务状态、到期时间和脱敏请求编号，不直接改配额。不要在有在途任务时清理任务表或用量凭证。
- 记忆只接受真实用户原句或用户更正。编辑、删除、清空、暂停/恢复及时区变更推进 epoch 与消息边界，旧提取、索引、摘要和流式结果不能回写。界面历史保留，后续模型上下文排除边界之前的历史。新消息可以重新明确提供事实。
- 主动联系按账号本地日唯一建单，站内消息与 outbox 同事务创建；默认关闭、事件模式、22:00～08:00 免打扰和私密预览。活跃聊天和最近六小时互动不联系，连续未读增加间隔，最多退避至 30 天；读过的联系仍保留频控历史。
- 每次投递重新校验偏好版本、角色 epoch、事件来源/内容版本和设备完整指纹。设备成功回执不重发，404/410 只移除仍匹配的旧订阅。临时失败退避，联系最多保留两小时；载荷和推送 TTL 同时限制到下一免打扰开始、本地午夜或联系期限。SW 丢弃过期载荷并限制点击为同源路径。
- 网络成功与数据库确认之间仍存在崩溃窗口。系统用稳定通知 tag 收敛重复展示，不能承诺外部推送恰好一次。用户修改偏好前已经送达外部推送服务的载荷无法撤回；默认私密预览减少离线设备泄露细节。
- 管理员 `operations.generationQuality` 和 `operations.taskQuality` 按服务、模型、版本等聚合最近最多 1000 条样本，包含成功/失败、耗时及已知/未知用量；不返回聊天正文、密钥或设备端点。未知成本保留 `null`，合法零成本保留 `0`；它不是完整供应商账单。

## 备份与回滚

数据库、上传文件和 `KEY_ENCRYPTION_KEY` 必须成套备份。保留 JWT/VAPID 配置和对应 Git/镜像版本；只恢复数据库会留下缺图或无法解密的 BYOK。逻辑导出期间先停止应用写入，上传卷做同期快照；验证导出退出码和非空文件，并在隔离实例试恢复，不通过日志打印正文或凭据。

回滚时停止应用，恢复匹配旧镜像的数据库、上传快照和配置，再启动旧镜像并检查健康探针及登录/媒体读取。当前开发基线不支持跨版本逆向 SQL；只回滚镜像而保留不同 schema 不属于有效恢复。若无需保留开发数据，可重新创建空库并使用当前基线初始化。

## 真实模型质量验收

自动回归使用合成上游、真实 MySQL 和模拟推送，验证业务与故障边界，不证明自然度或留存收益。上线前使用获准的合成资料，在实际选择的模型上逐例执行；记录版本、模型、首片段/总耗时、已知成本及下列评分。每例同时检查界面状态、最终保存消息和实际用量记录。

| 样本                                            | 必须观察到的行为                                |
| ----------------------------------------------- | ----------------------------------------------- |
| 同一问题分别使用克制/活泼预设与短/长回复        | 风格有可辨差异，遵守长度及回复语言              |
| 初识与亲密阶段表达同一关心                      | 关系节奏变化，身份透明，不强迫依赖或因离线惩罚  |
| “今天工作很累”与对角色的明确批评                | 区分生活压力与关系冲突；助手自己的安慰不加分    |
| 三次连续补充、停止、刷新、网络断开重连          | 所有已接受输入仍在上下文，无重复气泡或重复用量  |
| “我的猫叫团子”→“现在叫麻薯”→删除                | 更正生效，后续回复不复述被忘记的旧名            |
| 中文、英文、日文、韩文的“明天有面试”            | 日期锚定来源时区；取消/完成后不再当未来计划联系 |
| 暂停记忆后继续聊天，再恢复                      | 暂停期间不学习、不召回；恢复不补学旧消息        |
| 图片生成中忘记、切换会话、失败后重试            | 旧上下文结果不落库、不串角色，失败额度正确补偿  |
| 语音播放中停止/补发/切换账号                    | 立即停播，迟到录音或转写不发送到新会话          |
| 主动联系关闭、DND、离线到期、连续忽略、读后重试 | 频控和隐私符合偏好，不出现重复站内消息          |

每例按角色一致性、事实正确、自然表达分别打 1～5 分；记录不合格原因为后续修复样本。归属、遗忘、重复扣费或偏好绕过属于发布阻断；主观质量需人工审阅。C 端实际留存、付费和延迟分布需上线后的真实统计再判断，不从合成测试推断提升比例。
