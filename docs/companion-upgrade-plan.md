# C 端陪伴体验升级执行与验收记录

本清单对应 2026-10-20 用户授权的完整四阶段升级。工作在 `codex/companion-experience-upgrade` 分支进行；每批实现、测试、修复后提交。未验证的能力保持未完成，不以单元测试代替真实用户流程验证。

## 全量范围

- [x] 角色行为：统一上下文；关系阶段、当前情绪与原因进入每轮对话；情绪惯性与恢复；只分析用户互动，避免助手自我加分。
- [x] 角色创作：表达方式、长度、主动程度、关系节奏、对话示例；预设差异；四语界面；新字段校验和持久化。
- [x] 流式聊天：分句展示、停止、补发、长句兜底、重连恢复、刷新恢复、稳定消息标识、请求幂等。
- [x] 生成结算：部分结果保存、取消与断线区分、多实例取消、并发限制、重试去重、额度与供应商实际用量分开。
- [x] 记忆：会话摘要、语义召回、事实来源、更正失效、事件时间、跨角色隔离、上下文预算。
- [x] 遗忘：删除/更正同时使索引、缓存和衍生摘要失效；暂停记忆、编辑和忘记入口。
- [ ] 主动陪伴：显式偏好、IANA 时区、免打扰、频率、事件驱动、忽略退避、发送前复查、推送与站内记录去重、隐私预览。
- [ ] 多模态：文字/语音/自拍共享角色上下文；语音播放取消；各媒体失败独立反馈、重试与结算。
- [ ] 运营：版本化提示词、任务用量/耗时、脱敏日志、可配置预算/超时/降级、功能开关、故障恢复与备份文档。
- [ ] 质量：真实业务回归、并发/失败/归属/重试测试、四语检查、浏览器验证、生产构建、逐项最终审计。

## 执行规则

保留 Express、tRPC、React、MySQL 和已有账户/配额基础。不调用真实运营 AI、邮件或支付进行自动测试。独立 MySQL 测试库由现有脚本验证隔离和迁移。

用户补充授权：当前为开发阶段，不考虑任何旧表、旧接口、旧数据兼容；数据库和服务可以随时重新迁移和部署。后续删除过时字段与重复路径，按最终 schema 重建初始化基线，重建专用测试库和开发部署验证。

运行时缺少技能所述 `protocol_request`、`agent_workspace_import` 和持久任务图工具，且 `.agents` 目录为只读，因此使用本仓库文档、可用协作消息、独立只读审查和 Git diff 代替该技能的协议/导入机制。

## 第一批契约：角色行为基础

交付：纯函数行为规则与有界上下文、关系/心情注入真实聊天路径、持久情绪原因与恢复、角色风格/示例输入、调用用量和耗时记录、增量迁移、针对实际函数/路由测试。

硬验收：

1. 不同关系阶段生成不同行为约束，保持原角色身份及既有回复语言和长度偏好。
2. 工作/生活负面表达不被简单视为对角色的攻击；助手文字不会改变情绪分数；长时间离线不触发惩罚。
3. 新字段能在创建、编辑、读取中往返，拒绝越界或超量示例；四个语言包完整。
4. 聊天调用引用当前角色状态及示例，设置的事实不能越过用户/角色归属；用户可控内容明确为资料而非平台指令。
5. 用量记录不包含正文或密钥，供应商缺失用量标为未知，不以零代替；失败不重复结算。
6. 检查、针对回归、完整测试和构建有明确结果；独立审查发现的问题修复后才提交。

### 第二批契约：流式聊天、打断与恢复

交付：服务端持久化聊天任务及分句结果；鉴权/CSRF 的流与取消接口；前端实时分句、停止、补发、刷新/断线恢复；稳定请求和消息标识；额度和供应商成本分离；并发/重试/多实例取消测试。

硬验收：

1. 相同客户端请求 ID 重试不会再创建任务或扣额度；用户、会话、角色归属和年龄检查均保留。
2. 完整句或长度/等待上限内展示片段；片段有持久 ID 和序号，刷新后能恢复原来分段和顺序。
3. 主动停止与网络断开区分；断开不直接取消上游，取消状态在数据库共享，旧结果不能覆盖新轮。
4. 用户补发时停止旧任务，旧片段保留，所有已接收补充出现在新上下文；多设备同会话并发不能形成两套结果。
5. 失败、部分结果、停止、成功有明确状态和可预测额度规则；多次结算或补偿不会重复计量。
6. 外部调用不持有数据库长事务；进程重启时过期任务可明确结束和补偿，不能无限显示生成中。

### 第三批契约：可信记忆与语义召回

交付：可暂停的角色记忆、带来源的会话摘要、当前服务内的可配置语义索引、日期明确的事件、统一上下文预算与完整遗忘链路。

硬验收：

1. 事实来源仍只接受用户原文；对话示例、助手生成经历、未完成助手片段不能变成用户事实。
2. 摘要记录来源和生成边界；记忆删除、更正、清空会使引用它的摘要和索引失效。并发任务不能在删除后重新写回。
3. 语义检索只比较当前用户/角色、当前内容版本的有效记忆；同义异字案例能通过真实向量检索路径召回，模型维度/异常向量被校验。
4. Embedding 只使用已选择且支持该能力的服务及凭据；未配置或失败降级为现有召回，不静默切换另一数据接收方。
5. 相对日期锚定来源消息日期与用户时区；没有可靠日期不声称事件即将发生，过期事件不当成未来计划。
6. 提示词有总预算，角色规则、当前用户输入和必要事实优先；不得靠删除闭合分隔符的字符串截断实现预算。
7. 暂停记忆后不新提取、不生成索引或摘要，并有明确的编辑、删除、清空和恢复入口；四语界面与真实数据库回归通过。

实现约束：统一用户 IANA 时区供记忆与主动联系共用。记忆任务捕获角色 epoch，删除、更正、暂停/恢复及清空推进 epoch；清空另设原文消息边界，旧消息不会重新提取。索引绑定内容版本与服务/模型/凭据来源，摘要仅包含仍有效的用户记忆及来源链；派生调用提交前重新验证，查询返回后也重新确认版本。城市/职业等单值事实更正不能只靠字面相似度。总上下文预算与消息接收共用，先容纳所有已接受的连续补充，再分配记忆、摘要和旧历史，不事后静默丢弃输入。

### 第三批验收记录

- 新增来源类型、原文编号/时间/时区、内容版本、事件日期和有效状态；真实用户来源重新验证归属及完整原句。用户手动更正建立新来源，结构化单值事实更正不会把猫名覆盖成人名，强化后的内容可逐字追溯。
- 语义索引绑定内容版本、epoch、服务、模型和凭据来源，网关只保存哈希用于匹配。仅在当前服务支持且显式配置 embedding 模型时调用；其余情况保留词面召回，不换数据接收方。摘要由有效记忆与真实完整消息的原话组成，区分用户话题和角色建议，四语界面按结构渲染。
- 删除、更正、清空、暂停/恢复及时区变更均有失效边界；上下文同样排除此前用户消息与助手复述。准备阶段暂停不再发出外部调用，已发出的旧提取/向量/摘要不能回写，正在流式生成的旧上下文不能继续写入。
- 内部调用按实际尝试原子占每日预算，失败不退次数；保留供应商已知用量，未知与合法零分开。删除角色保留不含正文的预算凭证。新增管理员任务聚合统计、可配置总字符预算、超时、并发与功能开关。
- 真实 MySQL 回归覆盖同义向量召回、跨角色来源拒绝、准备/执行阶段暂停竞态、删除查询与更正索引迟到、清空后排队/运行中聊天、事件取消/完成失效旧计划、英文摘要原句及部分助手排除等。领域最新 66 项回归通过；最终全量结果提交前记录。
- 浏览器合成事实真实提取 → 查看来源消息编号 → 暂停（记忆仍可管理）→ 更正猫名（来源变为用户更正）→ 保存 IANA 时区 → 恢复 → 刷新验证持久化。截图 `output/companion-upgrade/memory-controls.png`。未调用真实外部 AI。
- 最终全工作区回归：113 个文件、839 项测试全部通过（含第四批准备的 7 项时区/免打扰纯规则测试，这两个尚未接线文件留待下一批提交）。TypeScript、ESLint、全仓 Prettier 和差异检查通过；构建通过。

### 第四批契约：主动陪伴、多模态和运营

交付：显式主动联系偏好、时区/免打扰/频率、事件驱动消息、忽略退避、可靠投递、隐私预览、语音/照片统一角色上下文、运营配置与发布手册。

硬验收：

1. 默认关闭未经用户同意的主动联系；按用户 IANA 时区决定免打扰，跨日和夏令时用例可验证。
2. 联系理由来自有效事件或已允许日常模式，连续未读时退避；发送前复查偏好、角色、事件和来源有效性。
3. 定时任务领取与站内消息写入幂等；多实例不会创建重复联系记录，投递重试不重复创建消息；推送预览不默认暴露私密原文。
4. 文字、语音、自拍复用角色和本轮状态；停止或补发同步取消播放；各类媒体失败独立说明与结算。
5. 按任务记录有限用量/耗时/版本，管理员只看聚合统计；未知成本不当作零，常规日志不记录正文或凭据。
6. 配置可限制并发、上下文、上游超时与功能开放；失败降级不改变用户的数据接收方。
7. 按开发阶段最终 schema 重建初始化基线，验证空库迁移、完整回归、时区专项、构建、浏览器核心流程和最终需求矩阵；逐批 Git 提交。
