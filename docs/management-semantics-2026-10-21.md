# Admin 语义关系与交互核查（2026-10-21）

## 结论与问题分级

页面应帮助运营者理解用户经历。原实现虽有卡片、单位和校验，仍按配置结构并列字段，跨模块因果关系需要使用者自己推导。

- P0：字段可编辑，但看不出哪几项共同决定实际效果。容易把“启用套餐”当作授予权益、把等级当作图片生成的全部条件。原因是依赖被拆到独立页面。改为用户经历链、分步编辑、同草稿关联编辑和规则试算。
- P1：完整预览在编辑区前堆叠大量状态，记忆容量和四种语言尤其占空间。信息量掩盖当前任务。完整预览改为按需展开，容量按关系等级查看继承规则，文案按语言切换。
- P1：图片素材使用固定比例裁切，管理者无法核对原图。改为完整显示，封面、轮播和通用图片提供原图弹窗；前台卡片预览明确保留真实裁切。
- P2：进阶执行参数与常用运营设置同等突出，备用服务参数与正在使用的服务混杂。按因果分组，进阶参数折叠，未使用参数标为备用；有错误时自动展开。

| 亲密度           | 有效互动 → 奖励与限制 → 积分等级 → 解锁           | 奖励按触发、结果、限制编辑；不显示无意义阈值；当前等级联动展示姿势、记忆、相处阶段 |
| 角色默认与上限   | 创建默认、资料长度与注入预算不同                  | 明确默认仅作用于新角色；会话标题与提示预算分别编辑，关联表达指令和上下文           |
| 情绪             | 用户表达 → 分数变化与恢复 → 短期语气              | 实际情绪纯函数试算，不把情绪分误当亲密度积分；恢复、受伤持续与门槛成组编辑         |
| 记忆             | 成功聊天 → 提取/去重 → 等级容量 → 召回回复        | 轮次与用户话语试算；查看等级实际继承容量，可创建独立门槛并明确影响等级范围         |
| 主动联系         | 平台开放 + 用户授权 → 时间/频率/未读 → 素材与投递 | 用实际资格纯函数说明拦截原因；默认偏好与全局限制分开，不能替用户开启               |
| 上传与录音       | 用途规则 → 格式/容量/时长 → 编码后请求体          | 代入文件大小、格式试算，显示 Base64 膨胀与请求上限，关联最短录音与语音执行         |
| 模型与工作流     | 用户密钥优先级 → 服务分支 → 模型/工作流 → 执行    | 仅展开当前服务相关参数，保留备用值；工作流标明当前是否参与任务，关联默认模型与预算 |
| 执行与回收       | 输入 → 排队 → 生成 → 分段交付 → 清理              | 按执行先后组织常用参数，后台保活与调优折叠，关联客户端等待与服务                   |
| 分页、播放与连接 | 内容数量、朗读方式、等待机制各自影响体验          | 倍速与默认值成组，浏览器声音与云端服务解释清楚，关联录音、权益、后台时限           |

所有关联编辑直接合并当前完整业务草稿，不独立保存或发布。关闭后回到原任务，原输入和关联输入均保留。工作流原始文本随编辑视图保留，关闭关联编辑器再打开仍可修复未完成的 JSON。

## 规则试算边界

- 积分与解锁使用 `getLevelByPoints`、`getPointsToNextLevel`；记忆使用 `memoryLevelRule`、`memoryInjectionK`、`shouldExtractMemories`。
- 情绪使用 `evolveCompanionEmotion`；通知使用 `proactiveContactWindow`；上传使用 `acceptsUpload` 与 `uploadDescription`。
- 试算只读取草稿与手工示例，不读真实用户内容、不发送通知、不调用 AI。通知通过时间资格仍需事件/日常素材和投递渠道，上传还需对应的真实文件与请求校验。
- 奖励说明对照 `server/relationship.ts`：文字、语音额外奖励使用严格大于；连续天数使用大于等于；长对话在阈值加一的准确轮次触发。

## 视觉与低成本改善

沿用既有主题和 shadcn/Radix 原子组件，无新增 UI 框架。正文 14px/1.5，帮助信息 12px/1.5；标题 18–20px；间距 8/12/16/24px；分组圆角 12px、主要容器 16px；颜色使用语义化 background/card/muted/primary/destructive；桌面任务导航 200px，窄屏自然换行。
