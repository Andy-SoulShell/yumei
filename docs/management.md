# 管理后台

访问站点的 `/admin`。后台复用站点主题、明暗模式、卡片与表单组件，支持桌面侧栏和手机分区菜单。它直接调用现有管理 API，不维护用户列表，也不要求创建管理员用户。

## 内容工作台

日常内容操作集中在“工作台、官方角色、首页、发布中心”。品牌与体验、业务规则、系统设置按任务分组，侧栏支持查找功能；手机保留四个常用入口和完整分组菜单。

工作台提供创建角色、编排首页和最近编辑入口，统计直接来自真实内容，不生成访问量或运营趋势。角色库支持名称、身份和兴趣搜索，按状态筛选或最近编辑排序；进入编辑再返回时保留筛选条件。“待发布”同时包含新增、更新和待下架，已归档内容可单独找回；复制角色会生成新的稳定标识。

首页分为精选角色、轮播、常见问题和展示设置。通过名字与封面添加精选，使用箭头排序；轮播和问答可新增、排序、移除并编辑多语言文案，新建后自动展开并聚焦。轮播间隔以秒填写，站内资源和完整 JSON 保留在高级入口。首页预览复用前台轮播与角色卡，展示当前未保存草稿，操作不会跳转或创建用户角色。

发布中心分别汇总官方内容与全部设置，显示每组实际变化。内容入口和设置入口均先展示完整变更与影响范围，经核对才执行发布。设置发布会预检已发布官方角色的字段兼容性，服务端仍执行最终版本、引用与领域校验。

## 密码与登录

在服务端 `.env` 中设置 `ADMIN_PASSWORD`（8–512 个字符），重启服务。可以运行 `openssl rand -hex 24` 生成随机密码。Compose 已传入此变量；未设置或格式不符时管理登录关闭，没有内置密码。

管理会话独立于用户会话，持续 12 小时；Cookie 为 HttpOnly、SameSite=Strict，在 HTTPS 下设置 Secure。服务端仅保存随机令牌摘要和密码签名。退出会删除会话，更换密码并重启后已有会话立即失效。登录每个来源地址 15 分钟最多尝试 5 次，所有实例共用数据库计数。

部署的数据库、存储、邮件连接和供应商密钥继续通过服务端环境管理；公开业务配置和管理页面都不返回这些密钥。

## 编辑与发布

1. 选择“官方角色”“首页、轮播与 FAQ”或业务配置分区。
2. 通过表单编辑；颜色字段提供色块、系统颜色选择器和十六进制输入，主题提供卡片选择及明暗实时预览，主色与背景色分别标注。首页角色引用显示名称与缩略图，图片支持预览、上传，数组可以上下排序，工作流节点和输入记录可以新增、删除。业务配置和首页也可切换 JSON，复杂工作流适合 JSON 编辑。多语言对象至少填写 `zh-CN`，其他语言缺失时回退中文。
3. 点击“保存草稿”。共享 schema 校验全部字段、引用和领域间约束，错误显示在编辑区。
4. 点击“查看发布变更”或“查看设置变更”，也可进入发布中心统一核对。确认后，官方角色与首页作为一份快照发布；业务配置的全部分区作为另一份快照发布。其他分区已保存的草稿也会一起发布。

保存与发布操作条会随编辑区滚动固定。上传、保存、发布及随后的草稿重读完成前，暂时锁定编辑、分区切换与退出，避免迟到的刷新清空新编辑。未保存修改会在切换分区、角色、重新读取或关闭页面时提示。草稿不会随窗口聚焦自动重载。写入或重读失败时保留当前输入。遇到并发修改时，界面保留当前内容并报告冲突；先复制要保留的编辑，重新读取后合并。并发令牌只防止覆盖，不保留历史版本。

分区和角色切换后回到编辑区顶部；JSON 和表单之间切换不会因对象键顺序误报修改。上传说明按发布字节数精确显示 B、KiB 或 MiB，前端与服务端错误提示共用格式。用户设置页的“当前实际运行模型”与聊天执行共用模型选择规则，包含默认模型、套餐锁定和 BYOK 的优先关系。

发布后服务端新执行读取当前配置；正在执行的任务保持其捕获的快照。前台窗口重新聚焦或定时刷新后同步。既有用户角色的人设和内容不会被官方角色编辑覆盖。

官方角色使用自动生成的稳定 ID，修改名字或人设不会改变来源关联。支持图片上传、排序、公开状态、归档及恢复。归档默认角色之前先变更首页的默认引用；发布前移除精选中已归档角色的引用。新图片上传采用当前发布的容量和格式规则；已保存的官方图片在规则收紧后仍可读取、引用和发布。

官方角色保存及发布复用实际创建角色的字段限制。业务配置发布也会核对当前已发布的全部官方角色；不兼容的上限可以保存草稿，但无法发布，上一发布版本保持有效。收紧字段上限时，先把受影响的官方角色调整到目标范围并发布，再发布新的业务限制。两套发布使用相同顺序的事务锁，并发操作也不能发布互不兼容的快照。

### 官方角色的编辑与发布

新增角色会生成独立标识，采用当前默认相处方式，封面可沿用已有素材。只需填写名字和人物设定；身份标签留空使用“AI 伙伴”，介绍留空使用人物设定前 100 字，外貌留空以封面为准。这些默认内容在预览和保存时保持一致，不会复制其他角色的人设或外语文案。多语言、外貌、兴趣、称呼、行为、排序及资源路径放在“更多设置”中，已有值会保留。

必填项、成年年龄、字数和行为限制随编辑即时校验，有错误时禁止保存，并在字段旁和编辑区底部列出具体问题。前台预览直接使用未保存内容，复用探索页角色卡与详情展示；可切换展示语言，缺少译文时回退中文。预览不会创建角色或开始聊天。

保存后点击“查看发布变更”，可看到当前草稿与同一版本已发布快照的差异：所有角色的新增、修改、下架，逐字段的发布前后内容，以及首页的待发布变化和涉及的默认、精选角色。其他角色已保存的草稿也在范围内。已有用户角色不会被覆盖，业务与运行配置不在此次发布范围。确认全部变更后才能发布；取消返回编辑，服务端仍以版本和完整校验阻止过期或不兼容发布。首页编辑入口使用同一发布确认流程。

## 直接调用 API

管理页面使用的就是 `/api/trpc` 下的现有接口。接口认证流程如下，`client` 为项目 tRPC 客户端；项目客户端已携带 Cookie 与匹配的 CSRF 请求头。

```ts
await client.management.status.query(); // 同时取得 csrf_token Cookie
await client.management.login.mutate({ password });

const draft = await client.productConfig.admin.getDraft.query();
const config = draft.config;
config.experience.pagination.conversations = 30;
const saved = await client.productConfig.admin.save.mutate({
  expectedRevision: draft.revision,
  config,
});
await client.productConfig.admin.publish.mutate({
  expectedRevision: saved.revision,
});
await client.management.logout.mutate();
```

自建 HTTP 客户端需要保留 `yumei_management` 与 `csrf_token` Cookie；所有写请求附上相同的 `x-csrf-token`。使用 tRPC / SuperJSON 编码，不能用普通用户 Cookie 或 `users.role=admin` 替代管理会话。

全部字段和调用契约见 [业务配置 API](product-config-api.md) 与 [官方内容 API](discovery-api.md)。

浏览器实际写入、发布和执行核对结果见 [2026-10-21 后台验收记录](management-browser-walkthrough-2026-10-21.md)。
