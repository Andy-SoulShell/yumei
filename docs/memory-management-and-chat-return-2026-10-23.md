# 记忆管理与当前会话衔接

日期：2026-10-23。

## 使用流程

记忆页优先展示已保存的内容，支持搜索和分类筛选。每条记忆的正文占完整宽度，更正、置顶和删除移到卡片底部，使用带文字的触控按钮。记忆开关与账号时区、对话回顾、忘记全部分别按需展开。

更正时先编辑，再核对原内容和新内容，最后明确确认保存；删除单条和忘记全部也使用专用确认框。确认框不会在请求发出后立即关闭，操作中禁止重复提交，失败保留确认内容和更正输入，可以重试。页面保留处理状态及结果，成功后提供继续聊天入口。

## 对后续聊天的影响

- 更正和删除只影响当前角色的所有会话，不影响其他角色。
- 界面中的历史消息保留，不会被改写。后续回复停止使用该角色此前的聊天上下文和旧摘要，旧消息也不会再次提取为记忆。
- 更正替换对应记忆；删除单条保留其他记忆；忘记全部同时删除置顶和普通记忆。
- 已排队或生成中的旧回复可能停止。用户继续聊天时可能需要简短补充原话题。
- 记忆开启时，用户在新消息里再次提起的信息仍可能被重新学习。记忆暂停时，更正仍保存，但恢复后才用于回复。
- 置顶只防止自动遗忘，不改变事实内容或上下文。暂停、恢复和更改时区也会推进旧上下文边界；时区属于整个账号。

这些说明以现有后端的上下文失效、记忆任务边界和召回行为为依据，没有把“删除一条记忆”描述为删除聊天历史或永久禁止再次学习。

## 结果与返回路径

聊天页进入记忆管理时，在 URL 保留当前会话编号。返回前读取会话并检查它属于当前账号和当前角色，成功操作后直接回到该条会话，避免误开该角色较新的另一条会话。收到写入成功回包后即可返回，不必等待列表刷新。无来源或原会话不可用时，明确提供打开最近会话的入口。

返回聊天后显示简短的上下文变化提示，原草稿继续保留，不自动改写或发送消息。未保存的更正通过页面返回、继续聊天离开前会再次确认；直接刷新或浏览器外部导航仍遵循浏览器行为，不承诺跨页保存记忆更正输入。

服务器确认成功后立即更新页面缓存。列表刷新失败单独说明并提供重新读取，不把已成功的写入报告成需要再次提交；后台读取失败也不会卸载正在更正的表单。其他页面更新或删除原记忆时，保留当前输入并要求核对最新版本。账号或角色切换后，旧请求回包不再更新新页面。

更正、删除 API 接受可选的内容版本。旧页面不能覆盖或删除另一处已更正的记忆；兼容已有 API 调用。对已成功的同内容更正重试直接返回，不再次推进遗忘边界或清掉用户后来继续的上下文。无需新增数据库迁移。

## 手机体验与验证

- 表单在窄屏采用完整宽度，主要按钮、筛选控件和确认操作至少 44px；小屏输入字号为 16px。
- 确认框有视口高度限制，长内容可滚动，原文与更正分别显示；保留键盘焦点、取消入口及操作中状态。
- 设置了独立的成功结果与继续聊天入口，沿用应用底栏的滚动留白。
- `pnpm test:memory`：2 个文件、27 项测试通过，覆盖确认、失败重试、重复点击、列表刷新失败、并发版本、更正输入保留、账号隔离和原会话返回。
- 服务端真实请求测试覆盖更正后的下一轮召回、旧历史仍可查看、版本冲突，以及重复更正不重置后来聊天。
- 全量回归：187 个文件、1586 项测试通过。TypeScript、ESLint、Prettier、生产构建与 diff 空白检查通过。

浏览器验收使用临时 MySQL、本地服务夹具和合成账号，不修改日常开发数据库，也不调用真实付费 AI 服务。已检查 390×844、320×568 手机视口与 1440×1000 桌面，中英文布局、失败重试、取消删除、刷新失败后重新读取、慢速刷新期间立即返回以及原聊天草稿保留。检查结果及截图保存在 `output/playwright/memory-*`；iOS / Android 系统键盘与真机触控仍需发布环境验收。
