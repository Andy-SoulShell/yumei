# 手机键盘、横竖屏与安全区域专项验收

日期：2026-10-23。范围：聊天输入、生图弹窗、设置表单、记忆更正与返回聊天。

## 发现与修复

| 问题                                                                 | 修复                                                                                                                               |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 输入框失焦后立即退出键盘布局，真实键盘尚未收起，输入与按钮跳到键盘后 | 已识别键盘时保持高度和顶部偏移，等可视区域恢复再清理。支持从输入框切到按钮、确认弹窗及关闭动画。                                   |
| 安卓键盘展开期间旋转，新的压缩高度被当作正常高度                     | 旋转时参考原宽度保留高度基线，横竖屏往返不丢失键盘状态，键盘关闭后恢复普通布局。                                                   |
| 设置或记忆表单缩小时，焦点仍留在屏幕下方                             | 在布局更新后检查焦点与滚动容器、页面操作栏的位置，只补偿尚未完成的滚动；可见输入不额外移动，手动平移不抢回焦点。                   |
| 玻璃模式隐藏全局顶栏后，仍预留顶栏高度和滚动偏移                     | 键盘展开时清理对应留白，保留页面自己的操作栏和安全区域。                                                                           |
| 矮横屏中长草稿、引用、额度与会话提示挤出发送区域                     | 依据可用高度限制输入框和输入面板，减少键盘状态下的间距；超长面板可滚动。记忆更正、图片恢复及会话提醒放入消息滚动区，保留全部说明。 |
| 生图弹窗聚焦选项时卷走关闭按钮和标题                                 | 内容独立滚动，关闭按钮留在外层；打开时聚焦标题并保留顶部位置。                                                                     |
| 浮层只避开固定边缘，未完整处理刘海、侧边安全区与键盘                 | 普通与确认弹窗共用安全区域内的中心、宽度和最大高度；记忆确认保留窄屏限制。                                                         |
| 长提示按整个布局视口限高，横放时可能超过键盘上方空间                 | 提示依据实际可用高度限高、可滚动，手机左右边距避开安全区域；横屏触摸输入字号保持 16px。                                            |

表单较长时，通过所在区域滚动查看输入、保存按钮及结果，无需把全部内容压在同一屏。极矮横屏下辅助说明可以滚动阅读，输入与发送仍有独立的可用区域。

## 浏览器场景

使用 Chromium、WebKit 两种引擎，分别检查标准和实验玻璃模式。每种组合覆盖以下四组场景；中文、英文、日文、韩文分别检查，输入同时包含中英日韩及多行内容。

| 场景                   | 正常布局 | 键盘上方可用高度 | 顶部平移 | 模拟安全区域       |
| ---------------------- | -------- | ---------------- | -------- | ------------------ |
| 小屏竖放               | 320×568  | 240px            | 0        | 上 20px、下 16px   |
| 竖放与视口平移         | 390×844  | 320px            | 65px     | 上 47px、下 34px   |
| 刘海屏横放             | 844×390  | 190px            | 0        | 左右 47px、下 21px |
| 宽屏横放、布局同步收缩 | 932×430  | 210px            | 0        | 左右 59px、下 21px |

每组实际检查：

- 聊天多行草稿、发送按钮、失焦到键盘收起的过渡，生图打开和关闭后保留草稿。
- 生图标题、关闭入口、姿势与底部上传入口；逐项滚动并检查位置与实际命中区域。
- 设置单行和多行输入、保存、成功提示；记忆更正输入、核对、确认、成功、返回原会话及草稿保留。
- 额外检查引用草稿、安卓键盘展开时旋转及旋转回来、保持焦点收键盘、视觉视口平移、捏合缩放，以及设置和记忆操作失败后的重试。

## 验证与证据

- 16 组核心场景与 4 组连续旋转、失败重试补查全部通过，共 1044 项浏览器检查、160 张独立状态截图。逐项校验输入、主要按钮和提示的位置，并检查实际点击命中区域。
- `pnpm test:acceptance`：41 个文件、464 项测试通过，包含键盘失焦保留、旋转恢复、焦点滚动、手动平移不抢滚动，以及提示留在消息区的回归。
- 完整隔离数据库回归：187 个文件、1637 项测试通过。
- TypeScript、ESLint、Prettier、生产构建与 diff 空白检查通过。
- 浏览器证据保存为本机 `output/playwright/keyboard-*`，最终汇总为忽略目录中的 `tmp/setup-flow-lab/keyboard-final-report.json`，过程记录位于同目录的 `keyboard-*` 文件。

使用临时 MySQL、合成账号和隔离应用，保存、更正和返回均操作真实本地接口。失败路径使用浏览器响应夹具；为允许 WebKit 拦截这些请求，补查时在专用浏览器中停用 Service Worker。没有修改日常开发数据库，也没有调用真实付费 AI 服务。验收完成后清理临时服务与凭据，保留原有开发服务。

键盘由受控 `visualViewport` 高度、偏移和布局收缩模拟，安全区域使用测试样式注入。此检查验证浏览器布局、滚动与交互，不等同于 iOS / Android 真机系统键盘、候选栏、旋转动画或系统手势验收。
