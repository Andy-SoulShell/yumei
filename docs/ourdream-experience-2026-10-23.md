# Ourdream 参考体验与 YUMEI 功能调整

本轮按 Ourdream 的发现、创建、聊天、生图、社区及账户路径调整 YUMEI。视觉使用现有 YUMEI 品牌和图片，没有复制参考站账户的聊天或付费素材。

## 已接通的流程

| 用户任务       | 当前实现                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 找到角色       | 首页直接浏览目录，搜索、风格、成年年龄、性格标签、排序和账号收藏；手机两列卡片，详情分为资料、场景和图片。                       |
| 创建角色       | 六步渐进设计器，游客草稿登录后继续，提前展示角色名额；确认资料后创建并进入聊天。创建请求有稳定标识，超时重试不会重复创建或扣币。 |
| 聊天           | 桌面会话列表、消息、角色面板；手机角色抽屉；复制、引用、朗读、编辑消息及换一种回复。编辑和换回复创建新会话分支，原历史完整保留。 |
| 生图与作品     | 独立图片/合照/视频工作台，真实模型能力和用量检查；继续使用已有持久任务、排队、失败返还、恢复和相册。                             |
| 社区与创作     | 公开创作者资料、角色提交、独立运营审核、下架、社区浏览和创建私人副本后聊天。私人聊天、记忆、个性化昵称及音色不随发布公开。       |
| 金币与邀请     | 钱包、赠币与实付金币分账、消费明细、充值入口、签名支付回调、退款追偿、首次实付充值后的邀请奖励及退款撤回。                       |
| 创作者商业流程 | 其他用户消费实付金币产生分成；赠币和自用不产生收益。收益保留期、可结算金额、幂等结算申请、人工核验与支付凭证记录。               |

## 运营启用与真实支付

- 入口：`/admin/billing?edit=economy`。保存草稿后仍需在发布中心发布，前后端才使用新规则。
- 配置位于 `billing.economy`。已有站点默认保持原计费规则；明确启用金币后，金币替代生成次数额度，角色数量、功能权益和请求频率仍按原规则执行。
- `billing.mode = none` 继续表示自托管不限额；启用实际金币计费需选择 `free` 或 `lemonsqueezy`。
- 金币成本、首次赠币、充值包、订阅周期赠币、邀请奖励、分成、待确认天数和最低结算额均可编辑。代码中的初始值是 YUMEI 的可配置起点，不承诺等同于参考站的实时价格。
- 充值需要真实 Lemon Squeezy 变体、结账链接，以及服务端 `LEMONSQUEEZY_API_KEY` 与 `LEMONSQUEEZY_WEBHOOK_SECRET`；订阅和金币包不能共用同一个变体。使用既有 `/api/billing/lemon-webhook` 接收订单和订阅支付事件。
- 只有签名回调确认支付才入账，返回钱包页面不表示支付成功。测试订单与正式订单隔离，由 `LEMONSQUEEZY_TEST_MODE=1` 选择测试环境。
- 当前创作者结算采用人工流程：运营核验、联系账户邮箱安排实际支付、记录外部支付凭证后标记已支付。申请和审核按钮不会自动转账。
- 审核与结算入口：`/admin/commerce`，使用独立管理会话。

## 资金与恢复规则

- 同一用户的钱包操作在用户行锁内执行，所有入账和返还都有唯一事件键。
- 优先消费赠币，实付部分按订单分配；失败返还原来的币种和金额。
- 聊天已经持久化可见回复时保留一次计费；没有回复时返还。
- 订单退款按比例回收金币，不把已消费的余额悄悄归零；不足部分形成追偿余额。
- 订阅发票即使先于订阅快照到达，也会排队并恰好授币一次；发票退款撤回对应赠币。
- 创作者收益关联实付订单，订单退款会扣回对应收益；已被扣回的收益不能被标记为已支付。
- 私有财务记录纳入个人数据导出，账户删除清理关联记录；公开角色图片只在审核通过后对游客开放。

- 本轮全量自动测试：195 个文件，1683 项通过。
- 体验验收测试：44 个文件，474 项通过；角色发现专项 86 项通过。
- 新增独立数据库集成测试覆盖并发扣币、重复回调、退款乱序、赠币/实付币返还、邀请撤回、发布权限、审核版本、收益与结算、跨账号冲突及聊天分支。
- 本轮中英日韩四语 × 11 条路由 × 横竖两种视口，共 88 次页面检查，无页面或主内容区横向溢出，无未翻译键名。覆盖首页、角色目录、创建、生图、设置、记忆、钱包、创作者、社区、公开主页和聊天。
- 390×430 短视口实测结算确认按钮 44px；844×390 横屏实测资料保存按钮 44px。资料和发布草稿经刷新恢复，结算退回后再次申请生成不同编号，社区角色可以直接进入聊天。
- 浏览器验收使用独立数据库和合成测试账号，没有向参考站发送聊天、生成、充值或支付请求。

本轮没有接入参考站专属的角色包商城、比赛活动或自动出款服务。相应入口没有使用虚构的销量、点赞、收益或成功支付状态。

## 本次完整验收修复

- 支付回调不再取决于订阅计费模式；免费套餐搭配金币时也能到账。未配置支付密钥、未验证邮箱和不限额模式会明确阻止充值。
- 充值先保存稳定请求编号和金币包条款，钱包可找回待确认任务；同一个未确认金币包优先继续原付款。后台调价或下架不改变已发起订单的金币数量，已确认的链接不能再次发起付款。
- 订单缺少数量时，以签名订单中的明细编号调用支付商 API 核实，不能默认按一份入账。合法折扣订单可以入账；收益按订单实付金额（扣除税金）计算。
- 钱包补齐待确认充值、继续付款、过期说明、确认订单及退款金额与收回金币数，邀请链接可复制，重复绑定同一邀请码在首次充值后仍返回原结果。
- 创作者修改使用独立待审核快照，线上批准版本继续公开。退回修改保留线上版本；通过后原子替换，旧版本媒体进入回收队列。审核和创作者重新提交都会检查版本，防止过期页面覆盖新提交。
- 已发布、待审核和退回内容均能修改送审；下架有确认和结果反馈，管理端补齐已发布角色下架、结算历史和支付凭证展示。
- 收益改用固定货币精度：10000 单位等于 1 美分。后续金币定价调整不改变已有收益。历史 `coinsPerUsd` 仅保留为迁移兼容参数，在普通配置表单中只读。
- 创作者资料和发布表单按账号保留当前标签页草稿；保存中禁止改动，失败保留输入，结果以就近提示和全局通知反馈。验证邮箱会发送验证邮件，并保留钱包或创作者页的回跳地址。
- 结算先确认金额再保留收益，网络重试复用同一个请求编号；已处理后新申请使用新编号。退回释放金额，已支付必须记录实际外部支付凭证。
- 社区角色场景独立保存并进入聊天提示词，避免长场景挤入原有个性或自定义提示字段后无法创建角色。游客点击开始聊天后，登录会自动继续所选角色，并在失败时保留恢复入口；分享的旧角色也能独立找回，不受最新列表截断影响。公开作者名称连到 `/u/:handle` 主页；仅展示公开昵称、标识、简介和批准角色。
- 新增迁移 `0015` 与 `0016`，已在独立测试库及本地开发库应用。测试夹具和收付款记录均为独立库合成数据，没有发起真实充值、外部转账或付费生成。

充值明细数量的校验依据 Lemon Squeezy 官方 [Order](https://docs.lemonsqueezy.com/api/orders/the-order-object) 与 [Order Item](https://docs.lemonsqueezy.com/api/order-items/the-order-item-object) 定义。真实收款仍需运营配置自己的支付产品和密钥；创作者出款继续走人工核验与支付凭证记录。
