# 标准 / 实验玻璃模式交互与体验走查

日期：2026-10-21。分支：`main`。提交说明使用中文，未推送远端。

## 结论

实验开关现已作用于所有页面的公共材质，不再只改变导航。卡片、控件、聊天气泡、弹窗、抽屉、下拉菜单、搜索选择、日期选择、提示和消息通知均纳入同一套规则。文字和图片本体保持清晰，组件根据用途共享透色、描边或背景模糊，不给每个子组件重复加 blur。

对 C 端用户，最有价值的改善是：未发送内容不会因跳转设置而丢失；关闭弹层后能继续用键盘操作；翻阅历史不会被新回复拉走；手机聊天只保留一条角色导航；失败状态有恢复入口。玻璃层级和滚动遮挡的干扰也已降低。

标准模式仍适合作为默认，实验模式适合偏爱通透氛围的用户。本次工程走查支持“交互更连贯、阅读更集中”的判断；不能据此断言所有真实用户都会觉得“非常舒服”，也没有把模拟供应商返回当作真实 AI、音色或生图质量结论。

## 材质层级

| 表面                                                      | 实验模式的处理                                                                                     |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 全局导航、底栏、角色栏、输入托盘                          | 通透底色与一层背景模糊，使用统一高光和圆角。                                                       |
| 设置、角色、会话、相册、记忆及认证面板                    | 透色面板和细描边，不逐张模糊；内嵌卡片共享外层底色。                                               |
| 输入框、按钮、单选、复选、开关、徽标、头像占位和进度      | 使用透色或高光表现材质，保留选中、禁用、错误、焦点和语义主色。账号头像保留主色底以保证首字母可读。 |
| 对话框、确认框、抽屉、菜单、Popover、Select、SearchSelect | 使用统一独立浮层材质；打开后，后方导航停止模糊。子菜单或选择菜单打开时父浮层也退层。               |
| 日历、命令列表                                            | 独立展示时使用面板材质；位于卡片或浮层中时继承父表面，避免实色内层盖住玻璃。                       |
| 聊天气泡和图片文字托盘                                    | 保留较稳定的文字底色；用户气泡保留主操作色，照片上的白字使用深色托盘，图片本体不加滤镜。           |
| Tooltip、Toast、空态、错误与加载状态                      | 提示使用同一组透色和描边；文字状态不另叠模糊。                                                     |

实验模式的浅色 / 深色面板填充为 72% / 76%，独立浮层为 82% / 86%。正文比导航保留更多底色，避免后景细节争夺注意力。字段使用独立的透色 token，焦点环仍保留。

系统要求降低透明度、提高对比度或使用强制颜色时，导航、面板、控件、聊天气泡及浮层回退为实色。没有背景模糊能力的浏览器使用标准回退。

用户第二组截图中的矩形来自 `.page-toolbar.sticky::after`。实验胶囊已经有自身底色和模糊，不再需要这一块矩形渐隐；现已关闭该伪元素，保留圆角本体和柔和阴影。

## C 端舒适度判断

阅读连续性、输入安全感和操作可恢复性已有明确改善，比单纯提高透明度更能降低使用负担。实验模式现在能够在各页面之间保持相同的材质语言，用户不会从玻璃导航突然进入另一套实色弹窗。层级退让、稳定的聊天底色和系统实色回退，也降低了视觉混乱的概率。

仍需真实用户验证的重点是长时间聊天、强光下阅读、手机软键盘及低性能设备上的滚动。构建仍有约 1.03MB 主分块的体积提示；本轮没有用桌面截图推断移动端加载或耗电表现。设置页本身选项较多，未来应通过真实用户任务完成情况判断是否需要进一步渐进披露，而不是继续增加视觉效果。

因此建议保留标准默认和可选实验模式，以“能否更轻松地完成聊天、找回内容、处理失败”为体验判断依据，再通过真机和真实用户使用验证舒适度。
