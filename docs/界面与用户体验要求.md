## 1. 产品范围与要求口径

当前产品是面向 18+ 用户的 AI 角色陪伴 Web / PWA，核心循环是：**发现角色 → 开始聊天 → 积累关系与记忆 → 生成和回看内容 → 再次回来继续互动**。同时包含供运营方使用的独立管理后台。

需要区分两层范围：

- **当前版本基线**：角色、文字与语音、图片与视频、长期记忆、主动联系、订阅、隐私与售后。已实现的体验应作为回归要求保留。
- **后续产品方向**：PRD 规划的多元角色、用户边界档案、章节剧情、记忆候选确认和完整私密模式等。不能直接当成当前版本已经提供的能力。

以下使用「基线」表示应保留的已有约束，「改进」表示建议进入下一轮的要求，「规划」表示依赖后续产品范围确认的能力。改进项仍需排期和验收。

## 2. 体验目标

| 目标             | 对界面与交互的要求                                                      |
| ---------------- | ----------------------------------------------------------------------- |
| 容易开始         | 游客能先浏览；选好角色后再登录；首次聊天无需先配置模型、密钥或完整人设  |
| 容易选择         | 用性格、相处方式和示例帮助用户判断，角色图片之外必须有选择依据          |
| 适合长时间聊天   | 文字清楚、输入稳定、历史可找；新回复、键盘和动效不打断阅读              |
| 用户有控制权     | 可以停止生成、关闭音频、管理记忆、关闭联系、管理订阅和删除数据          |
| 状态可信         | 清楚区分未发送、已接收、生成中、失败与完成；不以跳转成功代替服务成功    |
| 费用可预期       | 操作前知道权益与额度，失败后知道是否计费以及何时恢复                    |
| 技术配置按需出现 | 普通用户先看到声音、回复风格和实际效果；服务商、Key、工作流放在高级入口 |

视觉气质应温暖、私密、偏角色与故事表达，同时保持长时间阅读的舒适度。陪伴文案不能用内疚、离开惩罚或关系焦虑推动使用和付费。

## 3. 信息架构与导航

### 3.1 当前结构

当前主导航包含创建、聊天、探索、生成、我的角色；桌面使用侧栏，手机使用底栏。设置从独立入口进入，Logo 返回公开首页。生成页目前主要承担「选择角色，再进入聊天生成」的中转功能。

### 3.2 建议验证的下一版结构

| 一级入口 | 用户目的           | 主要内容                                           |
| -------- | ------------------ | -------------------------------------------------- |
| 发现     | 找到想认识的角色   | 推荐、搜索、筛选、角色详情、创建入口               |
| 聊天     | 继续上一次互动     | 最近会话、搜索、会话历史、聊天内容                 |
| 作品     | 找到生成过程与结果 | 图片与视频任务、已生成内容、查看与下载             |
| 我的     | 管理个人内容和服务 | 我的角色、外观、通知、声音、订阅、隐私、账号、帮助 |

「创建」可作为发现和我的角色中的突出操作。以上四项导航是待验证方案；应先验证找角色、继续聊天、找作品、管理账号四类任务，再决定是否替换当前导航。

必须保留的导航规则：

- 手机进入聊天后，主要空间留给角色栏、消息和输入区，避免重复的全局顶栏与底栏。
- 从目录打开角色详情，返回先关闭详情，再返回上一级；保留搜索、筛选、已加载内容和滚动位置。
- 游客从某个角色开始登录，登录后继续原来的动作；认证失败或取消后能回到原上下文。
- 直接打开分享链接、无历史记录、角色失效时，都有明确且可用的回退入口。
- 桌面和手机可以采用不同布局，同一功能的名称、含义和状态保持一致。

## 4. 页面要求

### 4.1 公开首页与探索

- **基线**：匿名浏览，角色搜索，写实 / 动漫筛选，详情查看，加载更多，搜索条件可恢复。
- **改进**：手机首屏尽早出现可判断、可进入的角色内容；减少轮播、精选头像和目录之间的重复展示。
- **改进**：角色卡包含姓名、明确成年年龄、AI 标识、画风、简短关系钩子和少量性格标签。避免把关键文字放在复杂图片上。
- **改进**：详情补充相处方式、适合的话题或场景、关系节奏、一小段示例对话；有可用声音时提供试听。
- **改进**：主操作按状态显示「添加并聊天」或「继续聊天」；添加前说明剩余角色名额，超限时给出管理角色或可用升级路径。

验收：用户仅查看卡片和详情，就能说出两个角色在相处方式上的区别；搜索无结果时能清除筛选继续浏览。

### 4.2 注册、登录与首次使用

- **基线**：桌面认证弹框、手机独立页面；支持验证邮件、密码恢复、邮箱链接和失效链接处理。
- **基线**：明确 18+ 与 AI 身份；首次使用确认时区，已有账号保留已保存的时区。
- **基线**：界面语言与 AI 回复语言分别设置，不能把切换界面语言理解成改写历史内容。
- **改进**：引导只收集开始体验所需的信息，可选偏好允许稍后填写；不要连续堆叠多个阻断弹框。
- **改进**：邮件已发送、可重发、链接失效、验证完成、登录失败都有清楚的下一步；普通用户无需理解认证服务的技术错误。

验收：从角色详情开始注册并完成验证后，能继续该角色的聊天流程；原筛选条件和普通草稿不丢失。

### 4.3 角色创建、编辑与管理

- **改进**：提供快速创建路径，先完成形象 / 预设、名字与必要性格；外貌细节、示例、音色和提示词渐进展开。
- **改进**：进入创建页即显示可用名额；不要等用户填完长表单才发现无法创建。
- **改进**：预设载入后清楚展示当前选择，避免已选角色仍被长列表挤出视线；创建成功提供直接聊天的主操作。
- **基线**：普通草稿按账号和表单隔离；切页、返回与刷新后可恢复。切换预设覆盖修改前明确确认。
- **基线**：文件预览、上传中、失败和需重新选择的状态可见；密码、Key 不进入普通草稿。当前草稿恢复范围为本标签页，不承诺跨设备恢复。
- **基线**：角色软删除、回收站恢复与永久删除有不同说明；永久删除前列明受影响的数据。

验收：编辑后切到其他页面再返回，普通内容仍在；更换预设可取消；保存失败不清空输入，保存成功不误清理更新后的草稿。

### 4.4 聊天

- **基线**：角色栏显示当前对象与 AI 身份，并能找到记忆、关系、媒体和角色设置。
- **基线**：空会话提供少量开场话题；快捷动作先填入草稿，用户编辑确认后再发送。
- **基线**：发送、等待、流式回复、停止、未发送、失败和重试有可区分的表现。停止后保留已有内容，刷新能恢复当前轮状态。
- **基线**：首次进入定位最新消息；用户上翻阅读后不被新回复拉回；提供回到最新位置的操作。
- **基线**：输入自动增高但不挤占整个屏幕；中文输入法确认不误发，手机 Enter 换行，发送由明确按钮完成。
- **基线**：引用预览与本次回复分开，取消或更换引用保留正文；已发送引用可定位原消息，找不到时说明原因。
- **基线**：消息复制、引用、朗读在点击菜单和触屏长按中均可达；滑动阅读不触发长按。
- **基线**：聊天草稿、引用和异步结果按账号与会话隔离；切换后旧结果不得进入新会话。
- **改进**：关系与心情信息保持次要层级，不反复打断对话；完整生成错误留在对应消息附近，不能只用短暂 Toast。

验收重点：长会话、生成中上翻、键盘弹出、停止后补发、断线刷新、引用跨页定位、快速切换会话。

### 4.5 语音

- **基线**：录音有可见状态及取消入口；松手后先转写预览，允许修改、取消、确认发送，保留原文字草稿。
- **基线**：重复确认不重复提交；麦克风拒绝、无声音、转写失败时仍能继续文字聊天。
- **基线**：运营方已提供服务且用户有权益时，无需填写个人 Key 即可选声音、试听、保存并使用。
- **基线**：播放状态、停止、语速和自动朗读可控制；未保存的选择与当前生效音色不能混淆。
- **改进**：优先展示声音风格和试听效果，供应商品牌与个人 Key 放在次要或高级入口。

验收：拒绝麦克风权限不会阻断文字；切换会话停止旧播放，迟到的转写不出现在新会话。

### 4.6 图片、视频、任务与作品

- **基线**：生成前说明所选角色、参考素材、场景 / 动作、所需权益与实际额度；上传前可查看处理范围说明。
- **改进**：图片补齐与长耗时相匹配的任务界面，能识别排队、生成、完成、失败；刷新或离开后仍可找到同一任务。
- **基线 / 改进**：保留视频已有的持久任务恢复，图片逐步达到同样标准；重试同一提交不能误创建重复任务。
- **要求**：没有真实进度时用阶段说明，不显示虚假的精确百分比；不能取消的远端任务不提供误导性的取消承诺。
- **要求**：失败说明能否重试、额度是否返还；结果保存失败不能显示为完整成功。
- **改进**：作品入口同时呈现任务和完成内容；按当前已有媒体能力组织，不先承诺语音收藏或剧情纪念册。
- **基线**：原图、视频播放、下载、删除入口清楚；实际成片时长与请求时长不一致时显示实际值。

验收：生成期间刷新后能确认状态；完成后只出现一份结果；失败的计费结果符合该功能公示规则；删除后旧链接的访问行为符合隐私说明。

### 4.7 记忆与关系

- **基线**：用户可查看记忆原文和来源，编辑、更正、删除、暂停或忘记全部；说明当前是否学习和使用记忆。
- **基线**：区分聊天记录、长期记忆与关系状态，不能让用户误以为删记忆等于删聊天。
- **要求**：更正或遗忘前说明实际影响。当前实现会停止使用该角色此前的聊天上下文；其他长期记忆及界面历史仍保留。
- **改进**：更正后提供继续当前话题的提示或入口，减少用户修正单个事实后突然失去对话连续性的困惑。
- **基线**：离线不惩罚关系，不通过「不回来就失去她」一类文案驱动回访；解锁说明只陈述能力与条件。
- **规划**：记忆候选确认、敏感事实单独同意，以及以自然语言呈现多维关系状态，需要独立设计与实现。

验收：用户能判断暂停、删除单条、忘记全部分别影响什么；删除的事实不会从旧记录自动重新形成长期记忆。

### 4.8 设置、通知与个人服务

- **改进**：按用户任务分组：个人资料与安全、声音、回复风格、外观与语言、通知、订阅、隐私、帮助；避免默认展开长配置表。
- **基线**：各分区说明自动保存还是手动保存、作用范围及保存结果；失败保留选择并可重试。
- **基线**：显示模式支持浅 / 深 / 跟随系统，主题与语言按账号恢复；访客选择及新账号继承规则一致。
- **基线**：主动联系默认关闭；设备推送授权与主动联系授权分别说明，订阅设备不能自动开启联系。
- **基线**：以易懂的本地时间显示时区、免打扰和恢复时间，正确解释跨午夜时段；默认通知隐藏姓名和聊天细节。
- **基线**：订阅显示套餐、用量、周期与状态；能管理续费、账单和付款问题，已有订阅不诱导再次购买。
- **基线**：隐私说明、导出、单会话删除、邮箱确认注销、注销进度和售后工单有可找到的入口。

验收：普通用户不填 Key 也能使用站点已提供且有权益的能力；能从站内找到取消续费和删除账户的实际路径。依赖支付平台的步骤按其真实能力展示。

## 5. 视觉与公共交互规范

| 项目     | 要求                                                                                               |
| -------- | -------------------------------------------------------------------------------------------------- |
| 层级     | 每个页面有明确标题和主要任务；辅助说明、次要操作与危险操作保持不同层级                             |
| 色彩     | 复用现有语义主题色；错误、警告、成功、禁用和焦点在全部主题中可辨认，不只靠颜色传意                 |
| 字体     | 建议正文 14–16px、聊天正文不小于 16px，行高约 1.5–1.7；手机文本输入至少 16px。最终结合实际字体验证 |
| 留白     | 沿用现有间距与圆角系统，避免嵌套卡片重复留白；长文本保持适合阅读的宽度                             |
| 图片     | 角色卡、详情和作品采用各自稳定比例，加载时预留空间；关键脸部和正文不被控件遮挡                     |
| 材质     | 标准模式为默认，实验玻璃可选；正文底色足够稳定，避免每张卡片及嵌套层重复模糊                       |
| 浮层     | 菜单、弹窗、抽屉共用规则；子浮层打开时父层退让，关闭后焦点回到触发控件                             |
| 动效     | 只辅助反馈；尊重减少动态效果设置，轮播可暂停，不能靠动画表达唯一状态                               |
| 可访问性 | 键盘可完成核心操作；焦点可见，图标操作有名称，状态变化可被辅助技术识别                             |
| 触控     | 主要操作、取消、播放和菜单目标至少 44×44px；解释不能只藏在悬停提示中                               |
| 对比度   | 建议验收目标：普通文字至少 4.5:1，大字与关键控件边界至少 3:1；逐主题检查图片背景与玻璃表面         |

系统要求降低透明度、提高对比度或浏览器不支持模糊时，应回退为清楚的实色界面。视觉模式不能改变功能可用性。

## 6. 移动端与响应式要求

- 窄屏无页面级横向溢出；长角色名、外语文案、错误和引用不挤出操作按钮。
- 适配顶部与底部安全区，固定工具栏、底栏和输入区不能遮挡内容或最终操作。
- 软键盘、候选栏、浏览器工具栏变化、横竖屏切换后，输入区与发送按钮保持可见，草稿和阅读位置保留。
- 保留原生滚动和缩放；弹窗内部滚动不带动背后页面，不能用全局手势拦截破坏浏览。
- 桌面侧栏可折叠；表单和聊天保持阅读宽度，内容库再使用宽屏栅格，避免把手机页面简单拉宽。
- PWA 安装后能处理登录失效和网络恢复；离线缓存不等于离线可调用 AI，断网时应明确说明。

建议验收视口：320px、390px 手机宽度，横屏及键盘缩小视口，768px 平板宽度，1280px、1440px 桌面宽度。关键键盘、录音、惯性滚动和推送另做 iPhone Safari / 安卓 Chrome 真机验证。

## 7. 全局状态与失败恢复

| 状态             | 用户必须得到的信息与操作                                     |
| ---------------- | ------------------------------------------------------------ |
| 加载             | 正在加载什么；长任务显示阶段；列表预留稳定布局               |
| 空内容           | 为什么为空，以及第一个可完成的动作                           |
| 搜索无结果       | 当前筛选和清除 / 调整入口                                    |
| 未登录或会话失效 | 登录入口和恢复上下文的说明，保留可安全恢复的普通草稿         |
| 权限或套餐不足   | 缺少哪项权益；可用的管理、升级或替代操作                     |
| 服务未配置       | 说明当前站点尚未提供此能力，区别于用户没有购买或没有个人 Key |
| 额度耗尽         | 使用量、周期、用户本地恢复时间；不显示无效的反复重试入口     |
| 频率或并发限制   | 说明是稍后重试还是等待当前任务结束，区别于额度耗尽           |
| 网络 / 上游失败  | 对应内容的状态、是否已接收、是否可重试、已计费情况，保留输入 |
| 保存失败或冲突   | 保留修改，指出失败范围；提供重试或合并路径，不能静默覆盖     |
| 删除             | 操作对象、影响范围、可恢复性、处理进度；不可逆操作明确确认   |

共通要求：按钮文字与真实状态一致；重复点击不产生重复副作用；局部失败尽量不阻断整页；关键提示可持续查看。

## 8. 内容、语言与信任

- 文案使用用户能理解的结果和动作，例如「选择声音」「今日额度明天 08:00 恢复」；技术详情按需展开。
- 当前支持的简中、英、日、韩应覆盖同一套核心流程，包括空态、错误、邮件、上传说明和付费管理。自然语言触发也需逐语言验收，不能仅检查界面翻译。
- 对日期、相对时间、免打扰和恢复时间使用用户时区；金额与计量单位明确，实际续费金额以支付平台信息为准。
- 在角色与聊天等关键位置明确 AI 身份；上传前说明参考图、录音和聊天可能发送到所选第三方服务。
- 不承诺实际未实现的绝对匿名、端到端加密或即时撤回第三方记录；导出媒体范围和账户删除边界与真实能力一致。
- 数据控制、停止生成和退出不能通过情感施压阻碍；普通售后入口与危机支持资源分别命名。
- 后续多元角色与关系产品使用中性称谓与可选代词，不预设用户性别、性取向或关系目标。

## 9. 管理后台要求

管理端以「找到内容 → 查看当前效果 → 就地编辑 → 保存草稿 → 核对全部变化 → 发布」组织。

| 场景     | 要求                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 寻找功能 | 分组导航、搜索、常用入口；页面与编辑对象有可恢复地址                             |
| 内容编辑 | 先展示角色库、首页画布、主题和套餐效果；字段在具体任务中出现，高级 JSON 按需展开 |
| 表单     | 名称、单位、范围、依赖与字段错误清楚；图片可预览，列表可排序，语言缺失有明确回退 |
| 预览     | 展示未保存内容的实际前台效果，并区分预览、草稿和线上版本                         |
| 保存     | 未保存修改受保护；上传、写入和后续读取期间避免切换导致输入丢失；失败保留修改     |
| 发布     | 展示本次快照中的全部已保存变更及影响范围，不能让用户误以为只发布当前卡片         |
| 并发     | 冲突时保留本地修改并提示处理；不能把并发令牌描述成可回滚的历史版本               |
| 运营支持 | 工单可查找、回复、解决与重开；用户端明确在哪里查看回复                           |
| 手机使用 | 常用任务、编辑器滚动、固定保存区和返回路径可用，沿用前台主题与可访问性规则       |

后台发布应说明何时生效；官方模板修改不应让用户误以为自己的角色资料会同步被覆盖。

## 10. 优先级与下一轮范围

### 10.1 已补齐，应持续回归

根据 2026-10-23 的修复与服务记录，以下已有实现，不能重复当作未完成任务：

- 站点音色可用性、额度 / 限流原因与本地恢复时间、首次时区确认。
- 角色与设置普通草稿恢复、预设覆盖确认、角色详情返回路径。
- 单会话删除、数据导出、邮箱确认注销、私人媒体访问控制。
- 订阅管理、付款后权益核对、站内售后与管理端回复。

上述状态来自现有代码和记录；真实邮件投递、支付沙箱及真机能力仍需按发布环境验收。

## 11. 验收方法与指标

设计交付至少覆盖：页面结构、关键流程、手机 / 桌面布局、公共组件状态、空态与失败态、文案、权限与额度差异。

核心任务验收：

1. 游客找到合适角色，注册后继续原选择并发出第一条消息。
2. 仅填必要资料完成创建，并直接开始聊天；返回编辑仍可恢复草稿。
3. 长聊天中上翻、引用、打开键盘和接收新回复均不丢失阅读意图。
4. 录音转写后修改、取消或发送，不影响原草稿且不重复提交。
5. 图片 / 视频生成后离开并刷新，能找回同一任务、结果和额度结算状态。
6. 查看、更正和删除记忆时，用户能准确判断影响范围。
7. 额度耗尽后能知道恢复时间，已订阅用户能找到续费管理和付款帮助。
8. 关闭主动联系与设备推送、导出数据、删除会话和注销账号都有可完成路径。
9. 管理员修改内容后能区分预览、保存与发布，识别本次发布全部变化。

建议观测首聊完成率、找到角色和创建的任务耗时、草稿丢失、生成状态找回、失败后恢复、取消订阅与数据管理任务完成情况。尚无实测基线的指标先采样，不虚构目标或改善幅度。

PRD 已提出文本首字 P95 < 2.5 秒、普通回复完成 P95 < 8 秒、图片失败率 < 5% 等目标。这些属于待真实服务验证的性能目标，不是当前已达成结论。测试应注明设备、网络、模型、语言和样本量；媒体任务另外衡量状态反馈与恢复能力。
